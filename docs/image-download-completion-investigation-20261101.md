## 已确认的问题与变更

下载失败的重试路径原来先等待退避，再在 finally 关闭响应。对于仍然持有下载 lease 的响应，退避期间还占用名额。现改成先关闭响应再退避，仍然沿用同地址重试、最终切号和请求总预算。成功路径不变。此前一轮只有 9 次下载尝试超时，因此这个修正不能解释或消除几十秒的排队，不宣称显著提速。

新增数值诊断在 libcurl DONE 时、句柄重置前记录接收字节、TOTAL_TIME、STARTTRANSFER_TIME 及完成时刻，在业务读完时计算完成至读取结束的间隔。只在下载传输采集固定数值，不采集 URL、请求头、账号或 Cookie。

- curl_received_bytes：libcurl 报告的下载字节，压缩响应可能与应用解压后字节不同。
- curl_transfer_ms / curl_first_byte_ms：libcurl 记录的本次传输总时间 / 首字节时间。
- curl_completed_ms：本次 HTTP 调用开始到观察到 libcurl DONE 的时间。
- completion_to_read_end_ms：DONE 到业务读完或读取报错的时间，最小为 0。

这些时间仍受事件循环驱动频率影响，不是内核网卡收包时间，也不能单独证明服务器公网带宽是否不足。现有 body_ms 以响应关闭计时，会包含 EOF 之后的图片校验等等待；业务阶段 image_download_body 的耗时另行统计。取消主动移除句柄时没有 DONE，允许缺少新增字段。可选诊断失败不能改变传输成功或失败结果。
