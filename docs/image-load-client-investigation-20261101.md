# 压测客户端计时偏差与固定突发复测（2026-11-01）

## 结果与范围

本轮修正压测工具，并在服务镜像、设置和容器保持不变的情况下，完成一次固定 1 秒内发起 500 个同步生图请求的线上复测。495 个成功，5 个 `no_image_generated`；没有 504、空体 502 或最终 `image_download_failed`。未额外下载或解码图片。

本轮没有修改服务业务逻辑，也没有重新部署镜像。不能把本轮结果称为服务端性能优化已完成。它解决的是测量工具的偏差，给下一步服务端优化建立可信基线。

## 发现：HTTP 压测也重复创建 TLS 上下文

原压测器在每个生图请求和监控请求中调用 `urllib.request.build_opener(urllib.request.ProxyHandler({}))`。线上 Python 3.12.3 在创建默认 HTTPSHandler 时立即创建 SSLContext、加载系统 CA，即使请求目标为 `http://127.0.0.1:3005`。空闲时一次创建约 50.56 毫秒，500 线程同时操作时竞争明显。

使用独立子进程合成 HTTP 服务，仅返回 `{}`，不调用生图接口、不使用凭据。预建所有线程后统一释放，两个客户端交替运行两次：

| 并发 | 旧 urllib 客户端请求 P95 | 直接 HTTP 客户端请求 P95 |
| --- | --- | --- |
| 50 | 1.611 / 1.615 秒 | 76.85 / 42.47 毫秒 |
| 500 | 8.065 / 16.656 秒 | 0.813 / 0.649 秒 |

500 并发旧客户端创建 opener 本身 P95 为 7.621 / 16.367 秒。临时服务已停止，远程临时脚本已删除。该对照证明旧压测器存在显著额外开销，不能据此认定旧版所有延迟都源于客户端。

证据：`output/ingress_client_runtime_20261101.json`、`output/ingress_client_benchmark_20261101.jsonl`。

## 工具修正

- `scripts/loadtest_http_client.py` 使用显式 HTTPConnection，限制到 loopback HTTP，分别记录准备、连接、发送、等待响应头和读取正文时间。
- HTTP 400/502/504 保留真实状态与响应体长度，不被异常处理吞掉；连接始终关闭，响应正文限制为 16 MiB。
- 本地验证 5 项通过：成功响应、JSON 502、空体 502、正文大小限制、响应头超时；同时禁止默认 TLS 上下文创建，确认 HTTP 路径不触发它。
- 正式复测预先准备 500 个线程及请求正文，固定 1 秒发起，避免将线程启动和正文编码混入计时。
- `scripts/benchmark_load_client.py` 提供独立合成服务对照，可在没有线上凭据的情况下复现旧客户端问题。

集成期间首次尝试在 baseline 阶段暴露 `http` 模块与适配函数同名问题，尚未发送任何生图请求；改为直接导入 HTTPConnection 后验证通过。仅后续成功执行的一轮计入下面结果。

## 如何解释与旧数据的关系

前一轮旧客户端 500 请求平均耗时 84.442 秒，中间件平均 65.197 秒，平均差值约 19.245 秒。本轮分别为 80.990 秒和 79.240 秒，平均差值约 1.750 秒。这支持客户端开销已大幅降低，但两轮发起节奏不同，不能把差值全部当作修复收益。

旧轮实际发起跨度约 5.276 秒，本轮严格 1 秒；本轮对服务的瞬时压力更集中。旧轮成功失败统计仍有效，但旧客户端 P50/P95 混入工具开销，不能直接作为新工具下的性能基线。不能通过两个 P95 相减推导单请求阶段耗时。

## 当前剩余瓶颈与下一步

- 连接和请求发送均为毫秒级，当前 100 秒量级响应耗时不是压测器连接建立造成的；约 1.75 秒的平均差额仍可能包含 ASGI 计时范围外的排队等因素，尚未逐请求关联覆盖。
- 前 30 秒尚未读取图片正文，回调排队峰值已达 5.241 秒；该窗口图片循环内首页回调累计 CPU 约 8.806 秒。首页及鉴权准备的集中开销需要单独优化，不能归因图片下载带宽。
- 30—60 秒开始读取图片，下载等待人数峰值 157；60—90 秒峰值 292，读取正文约 803.5 MB，后半段才明显出现下载名额积压。
- 下载阶段仍有内核接收队列积压；curl DONE 到业务读取结束 P95 约 70 毫秒，不支持把下载长等待归因最终完成通知分发。
- 应优先在可重复本地 TLS/HTTP2 负载下复现集中建联及回调排队，再验证一个小范围改动。保留账号隔离、下载并发 64、2ms 回调时间片和现有超时预算；不盲目增加下载并发。
- 当前观测不能确认服务器带宽不足。网络接口数据包含代理或其他连接流量，单秒峰值不能代表持续可用带宽；本轮不进行无关网络扫描或额外图片下载。
