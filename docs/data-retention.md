# 图片和日志定时清理

图片管理、日志管理分别提供“定时清理”面板。两种策略独立保存、动态生效，无需重启。

- **保留最近（小时）**：仅删除创建时间严格早于“开始执行时间减去保留小时数”的数据，时间恰好等于边界的数据保留。
- **自动执行间隔（分钟）**：开启后每隔指定分钟数检查清理，后台调度检查精度约 5 秒。启用、修改策略或服务重启后等待一个间隔执行，不在启动时同步删除。
- **立即清理**：使用面板当前填写的保留时长，确认后在后台执行，无需开启自动清理。关闭页面不影响执行；服务本身需保持运行。
- 每种数据同时只执行一个清理任务。页面显示开始、结束、下次执行时间和最近结果，失败原因也可查看。

自动清理默认关闭。原 `image_retention_days` 仅用于首次初始化图片保留时长（天数乘以 24），原设置页的天数选项已移到图片管理；列表查询、图片保存及启动流程不再隐式删除图片。原“清理至指定剩余空间”和日期删除功能继续保留。

配置保存在 `config.json` 的 `data_retention`，例如：

```json
{
  "data_retention": {
    "images": { "enabled": false, "retention_hours": 24, "interval_minutes": 60 },
    "logs": { "enabled": false, "retention_hours": 720, "interval_minutes": 60 }
  }
}
```

保留小时数范围为 1～876000，间隔范围为 1～43200 分钟，均为整数。

## 清理范围

图片使用索引中的创建时间；未索引的旧本地图片使用文件修改时间。不读取图片内容计算过期时间。删除原图时同步处理缩略图、标签、存储索引及已记录的 WebDAV 副本；远端删除失败保留本地原图和索引供下次重试。删除后原图片 URL 会失效。

日志包含所有类型（调用日志和账号管理日志），不受当前页面筛选影响。实际清除 JSONL 中过期日志的请求体和响应体并更新分页、筛选索引及监控日汇总；监控历史统计因而只覆盖保留的数据。无法识别时间的记录保留。异步任务记录和数据库账号数据不属于本清理范围。

日志使用临时文件流式压缩，不把全部请求体、响应体同时加载进内存。主体压缩期间允许继续追加日志，最终追赶新日志后交换文件及索引；最终索引切换仍有短暂写入等待。压缩需要临时磁盘空间来保存仍需保留的日志，完成后移除临时文件。失败时页面可查看错误。

## 管理接口

以下接口需要管理员 Authorization：

- GET `/api/retention/{images|logs}`：策略及任务状态。
- POST `/api/retention/{images|logs}`：保存完整单类策略。
- POST `/api/retention/{images|logs}/run`，传 `{"retention_hours": 24}`：返回 202 并在后台执行。已有同类任务时返回 409；关闭自动清理仍可手动执行。

最后一次执行结果是进程内状态；策略持久化，任务状态在服务重启后重置。
